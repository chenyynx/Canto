# Hako「Agent 全权控制面」终版实施方案

> 版本 v4 · 2026-10-10 · 合并版（我方方案 + 外部方案对比后的吸收结果）
> 基线：`Hako-Client @62aa2f2` / `Hako @9437767` / `Hako-Adapter @6a47cf9`
> 事实依据：控制面可行性摸底报告（代码级，含文件+行号）
> 合并原则：架构骨架（两方案一致）；协议与安全模型采用外部方案的严谨版；UI 采用已定稿；实施文件映射采用我方的复用清单；内核零改动。

---

## 0. 结论先行

1. **agent 端 = 常驻 daemon + 薄 MCP 壳**（不是单纯 stdio MCP server——stdio 随 agent 会话退出，撑不起手机长连接与后台唤醒）。daemon 负责身份、设备注册表、命令队列、审计、对外监听；M 壳只做工具 schema 与转发，daemon 不在时自动拉起。
2. **安全层 = Noise 端到端加密**，无长期 bearer token，设备静态密钥即凭证。配对 `Noise_XX_25519_ChaChaPoly_SHA256`，日常会话 `Noise_IK`。中继只能盲转发密文。
3. **双连接器**：App 连接器（AC，订阅/配置/VPN/配对）+ Extension 连接器（EC，内核级操作），对 agent 呈现为「一台设备、两个通道」，按 `app.*` / `core.*` 命名空间路由。
4. **降级语义**：写操作三态 `applied` / `deferred`（持久化，隧道启动后生效）/ `rejected`；读操作降级返回带 `as_of` 缓存。能力四等级 F/A/S/O，绝不静默失败。
5. **防自锁**：`config.apply` 需健康检查通过 + 重连成功后被确认，超时自动回滚；agent 端点直连规则在 App 生成配置中永远置顶、overlay 不可覆盖。
6. **单主控**：同一时刻仅一个主控 agent，其余只读；主控切换需用户在手机端操作。
7. **工程策略**：协议/加密/状态机放纯 Swift 包 `HakoAgentKit`，与 agent 端共享测试向量，`swift test` 在 GitHub Actions macOS runner 上验证绝大部分逻辑；NE 胶水层 ≤200 行；Go 内核零改动。
8. **唤醒链**：Wake Gateway（无状态，发布方运营）把「唤醒某设备」转成 APNs 静默推送——APNs 密钥天然属于发布方，用户自建 agent 无法直接推送，此组件不可省。

# 第一部分：问题与目标

## 1. 问题定义

Hako 的全部管理能力（订阅、节点、规则、模式、隧道开关）只能由用户在 UI 里手动操作。目标是：

> **让一个 AI agent 完整接管 Hako 的全部管理能力，用户日常零操作。**

### 1.1 问题域分解

| # | 子问题 | 本质 |
|---|---|---|
| Q1 | **通道**：远端 agent 如何把指令送到手机 | 网络与 iOS 沙箱约束 |
| Q2 | **执行面**：指令到达后由哪个进程执行 | iOS 进程模型约束 |
| Q3 | **能力面**：内核 API 没覆盖的操作怎么补齐 | App 层逻辑 API 化 |
| Q4 | **产品面**：小白零门槛完成首次连接 | 配对体验与引导设计 |

### 1.2 硬约束（方案必须在其内成立）

| 约束 | 来源 |
|---|---|
| C1「允许添加 VPN 配置」弹窗必须人点 | Apple 系统设计 |
| C2 装完 App 必须首次打开一次 | Apple 系统设计 |
| C3 主 App 进后台主动断开内核连接 | `ClashCommandClient.swift:1306-1318`（应用自身行为） |
| C4 Extension 存活 = 隧道存活 | `PacketTunnelProvider.swift:36-50` |
| C5 内核控制面是 App Group 内 Unix socket（0600） | `bind/hako/clash_api.go:14,78-83` |
| C6 手机不能被服务端直连 | NAT |
| C7 构建只能在 macOS（Xcode 27 + Go 1.26.6）；CI 为免签名模拟器构建 | 已打通（GitHub Actions） |
| C8 APNs 静默推送密钥属于 App 发布方 | Apple 推送体系 |

## 2. 目标与非目标

### 2.1 目标（按优先级）

| 优先级 | 目标 | 可验证标准 |
|---|---|---|
| G1 | 远端 agent 全权管理 | 全部管理操作在线成功率 ≥99% |
| G2 | 首次连接零门槛 | 从装 App 到配对成功 ≤3 分钟、≤3 步、无需读文档 |
| G3 | 生产级可靠性 | 断线自动恢复；隧道关→开自动重连；命令不丢；绝不静默失败 |
| G4 | 开放能力 | App 不预置任何地址；任何符合协议的 agent 可接入 |
| G5 | 安全可信 | Noise 端到端；指纹进配对码防 MITM；最小权限；可审计可撤销 |

### 2.2 非目标

- 多主控 agent 并行写（v1 单主控，其余只读）
- 舰队管理 UI（协议层支持多设备，产品层后续）
- 内核协议功能增强（Go 内核零改动目标）
- Android / Windows

## 3. 设计原则

1. **官方行为零回归**：全部新增文件 + 插桩式修改（每处 ≤20 行），登记进 `PATCHES.md`。
2. **渐进信任**：配对确认 → scope 分级（observe/operate/manage）→ 敏感操作可选本机确认。
3. **可解释降级**：任何时刻双方都知道「能做什么、不能做什么、为什么」。
4. **无单点故障假设**：权威状态源唯一（设备侧）；agent 侧是缓存 + 队列。
5. **隐私最小化**：连接明细、订阅 URL 默认脱敏；第三方内容（节点名/日志）按不可信输入处理。

# 第二部分：总体架构

## 4. 架构总览

```
┌──────────────────────────────────────────────────────────┐
│ 用户自己的 agent 宿主（Mac / 服务器）                       │
│  ┌──────────────┐  MCP   ┌───────────────────────────┐  │
│  │ CC/Claude    │◄──────►│ hako-mcp 薄壳（随会话拉起）  │  │
│  │ Code/Cursor  │ stdio  └────────────┬──────────────┘  │
│  └──────────────┘            本机 unix socket             │
│                    ┌─────────────────▼───────────────┐  │
│                    │ hako-agent daemon（常驻）          │  │
│                    │ 身份密钥·设备注册表·命令队列/路由    │  │
│                    │ 状态缓存·审计日志·WS 监听           │  │
│                    └──┬───────────┬───────────┬───────┘  │
└──────────────────────┼───────────┼───────────┼──────────┘
              直连 wss │   出站    │           │ 唤醒请求
                       │           ▼           ▼
                       │      Relay（盲转发）  Wake Gateway（无状态）
                       │           │           │ APNs 静默推送
              ┌────────▼───────────▼───────────▼─────────┐
              │ iPhone：App 连接器 AC · Extension 连接器 EC │
              └──────────────────┬───────────────────────┘
                                 │ clash.sock (0600)
                                 ▼
                          ┌─────────────┐
                          │ Go 内核      │
                          │ Clash API   │
                          └─────────────┘
```

| 角色 | 所在进程 | 职责 | 生命周期 |
|---|---|---|---|
| daemon | 用户 Mac/服务器 | 身份、设备注册表、命令队列路由、状态缓存、审计、对外监听 | 常驻（launchd/systemd 一键安装） |
| MCP 壳 | agent 会话拉起 | 工具 schema、参数校验、结果整形；经本机 socket 转发给 daemon | 随会话 |
| AC（App 连接器） | 主 App | 配对、订阅/配置管理、VPN 开关、`device.json` | 前台在线；后台靠唤醒 |
| EC（Extension 连接器） | Network Extension | 内核级操作，经 `clash.sock` 驱动内核 | 与隧道同生共死 |
| Relay | 用户自建或第三方 | 盲转发 Noise 帧，看不到明文 | 常驻 |
| Wake Gateway | App 发布方运营 | 「唤醒某设备」→ APNs 静默推送，不存业务数据 | 无状态 |

### 4.1 关键技术选型

- **传输**：WebSocket 二进制帧，子协议 `hako-agent.v1`。设备主动出站，agent 被动接收。
- **安全层**：应用层 Noise（CryptoKit 原生支持 X25519/ChaChaPoly/SHA256，Swift 侧零第三方依赖）。内容端到端加密，局域网明文 ws 与中继都不削弱安全。
- **设备身份**：每台手机一把 X25519 静态密钥，Keychain 共享 access group，`AfterFirstUnlockThisDeviceOnly`（Extension 锁屏下可读，不进 iCloud）。`dev_id = dev_ + base32(SHA256(pub))[:16]`。
- **Agent 身份**：daemon 首次启动生成 X25519 静态密钥；私钥存系统钥匙串（macOS Keychain / libsecret），否则 0600 文件。
- **端点择优**：多端点并行尝试（250ms 错峰），首个握手成功胜出。通常顺序：局域网直连 → 公网 wss → 中继。
- **agent 端语言**：**TypeScript / Node 22+**（已定）。依据：主力 agent 宿主 Claude Code 本身即 npm 包（`@anthropic-ai/claude-code`，engines `node>=22`），用户已具备运行时；MCP 与 Noise（`@noiseprotocol/noise-c`）在 TS 生态均为成熟实现；社区贡献门槛低，利于长期扩展。分发用 `npx`（免全局安装），摩擦与单二进制等价。

# 第三部分：配对协议

## 5. 配对协议（Pairing Protocol）

### 5.1 信任模型

- 信任锚是配对那一刻的**物理接触**（扫码）或**人眼比对**（确认码 SAS）。
- QR 路径：手机从码中获得 agent 公钥（信任锚）；agent 从一次性口令确认手机。
- Bonjour 路径：无预共享信息，强制 6 位 SAS 确认码。
- 配对完成切换 `Noise_IK`：双方静态公钥互相已知，不再传输任何口令/token。
- **不做 TOFU 自动接受**：agent 公钥变化 → 手机硬停 `KEY_MISMATCH`，必须重新配对。

### 5.2 口令格式（二维码内容 = 粘贴口令）

```
hako://pair?v=1&k=<agent公钥 b64url,43字符>&s=<一次性口令 b64url,22字符,128bit>
  &e=<端点列表,逗号分隔>&n=<agent显示名,urlencode>&x=<过期unix秒>
```

- `e` 按优先级排列：`lan:<ip>:<port>`、`wss://host[:port]/path`、`relay:<relay-url>#<room>`
- `x` 默认 now+300s；总长约 200–260 字符，二维码 M 级纠错
- **App 不预置任何 agent 或中继地址**，全部来自口令
- 中继 room = `HMAC-SHA256(agent公钥, hako-relay-v1)[:16]`，不可由 room 反推公钥

### 5.3 配对握手（三条路径共用）

| # | 方向 | 内容 |
|---|---|---|
| 1 | 手机 → agent | Noise msg1：`e` |
| 2 | agent → 手机 | Noise msg2：`e, ee, s, es`。QR/粘贴路径必须与口令中 `k` 一致，否则中止 `PAIR_KEY_MISMATCH` |
| 3 | 手机 → agent | Noise msg3：`s, se` + 加密载荷 `pair.req` |
| 4 | agent → 手机 | `pair.res`（`accepted` / `need_confirm` / `rejected`）；`need_confirm` 后再发 `pair.done` |

`pair.req` 字段：`secret`（QR/粘贴必填，Bonjour 为空）、`device{id,name,model,os,app_ver,locale}`、`roles[app,ext]`、`push{apns_token?,env,topic}`、`caps`。

**确认码（SAS）流程**：Bonjour 强制；中继/公网默认启用（`pairing.confirm = auto|sas`）。双方各自 `HKDF(h, hako-sas)` 取 mod 10⁶ 得 6 位数，双端同屏比对，agent 侧确认后发 `pair.done`。120s 无确认作废。

**口令规则**：一次性（首个合法 `pair.req` 即消耗）；常数时间比较；3 次校验失败作废；同来源 5 次/分钟限流；daemon 同时只开一个配对窗口。

### 5.4 日常会话（Noise_IK）

手机 → agent：Noise msg1 + 载荷 `hello`：

```
role: app | ext
dev_id, proto: [1], caps: [...]
session_epoch: 7          # 仅 ext：隧道/内核重载代数
resume: {last_rx_seq: 118}
state_digest: <sha256 前 8 字节>
```

agent 查注册表：已知未吊销 → `hello.ok`；未知/吊销 → `auth.fail{UNKNOWN_DEVICE|REVOKED}` 后关闭，手机进入 `AuthFailed` **不再退避重试**并引导重新配对。

### 5.5 注册表与多设备

- **agent 侧**（`~/.hako-agent/state/devices.json`，0600）：`dev_id, pub, alias, created_at, last_seen, roles_seen, scopes, is_controller, apns{token,env}, revoked_at`
- **手机侧**（Keychain）：每 agent 一条 `{agent_id, agent_pub, endpoints, alias, scope, is_controller}`
- 一个 agent ↔ 多台手机：MCP 工具带可选 `device` 参数，多台未指定 → `DEVICE_REQUIRED`
- 一台手机 ↔ 多 agent：上限 3，同时在线，**仅一个主控**；写命令非主控返回 `NOT_CONTROLLER`
- 主控切换：手机「设置 › Agent 连接 › 设为主控」，推送 `evt.controller.changed`
- 吊销：手机侧「断开并移除」（尽力发 `bye{unpaired}`）；agent 侧 `hako_devices revoke`（立即关通道）
- agent 换机：`hako-agent export-identity` 备份身份，避免全体手机重新配对

### 5.6 重连退避

| 项 | 规则 |
|---|---|
| 退避曲线 | 1s 起 ×2，上限 60s，**full jitter** |
| 重置 | 稳定在线 ≥120s 后重置 |
| 立即重试 | 网络路径变化（NWPathMonitor）、App 前台、收到唤醒推送、Extension 启动 |
| 不重试 | `REVOKED` / `UNKNOWN_DEVICE` / `KEY_MISMATCH` |
| 多端点 | 并行错峰（§4.1） |

### 5.7 连接器状态机（AC 与 EC 各一份）

`Unpaired → Pairing → Connecting → Handshaking → Online → Backoff`；AC 额外有 `Suspended`（后台挂起，发过 `bye{suspend}`，可被唤醒）与 `AuthFailed`、`Disabled`。EC 退出前尽力发 `bye{tunnel_stop}`。

**断连恢复**：重连后 `hello` 带 `last_rx_seq` + `state_digest`；agent 补发未确认未过期命令；手机用去重表（最近 256 条/10 分钟）对重复 id 直接返回缓存结果——「执行了但结果没送达」不会重复执行。`state_digest` 不一致时 agent 拉 `state.get` 对账。

# 第四部分：双连接器消息协议

## 6. 帧与信封

UTF-8 JSON 帧封装在 Noise 传输消息内；单帧 ≤ 64KB，超出分页。Noise nonce 严格递增，天然防重放。

| 字段 | 说明 |
|---|---|
| `v` | 协议主版本，当前 1 |
| `t` | `cmd` / `res` / `ack` / `evt` / `ping` / `pong` / `bye` |
| `id` | ULID |
| `ref` | `res`/`ack` 引用的命令 id |
| `seq` | 发送方每通道单调递增 |
| `ch` | `app` 或 `ext` |
| `op` | 命令名或事件名 |
| `args` / `data` | 参数 / 结果或事件数据 |
| `ttl_ms` | 命令有效期，默认 30000，上限 600000 |
| `idem` | 幂等键，缺省等于 `id` |
| `if` | 前置条件 `{rev?, epoch?}` |
| `ok` / `status` | `res` 专用：`applied` / `deferred` / `rejected` |
| `err` | `{code, msg, retryable, hint}` |
| `meta` | `{rev, epoch, as_of?, stale?}` |

**版本与能力协商**：`hello` 声明 `proto` 与各通道 op 清单；agent 只调用对端声明过的 op，否则本地直接返回 `UNSUPPORTED`。新增字段向后兼容，破坏性变更才升主版本。

## 6.1 AC 命令集（`ch=app`）

| op | 参数 | 说明 |
|---|---|---|
| `app.state.get` | 无 | `{app_ver, vpn{status,stop_reason,on_demand}, active_profile, cfg_rev, scopes, controller}` |
| `app.vpn.start/stop` | `{reason?}` | 驱动 NETunnelProviderManager；首次未授权返回 `NEED_USER_ACTION{vpn_permission}`；目标态语义，幂等 |
| `app.profile.list` | `{cursor, limit}` | 订阅列表，URL 脱敏 |
| `app.profile.add` | `{url\|content, name?, auto_update_hours?}` | 规范化 URL 去重；已存在返回已有 id + `existed: true` |
| `app.profile.update/remove/select/refresh` | `{id, ...}` | `refresh` 返回节点数变化 |
| `app.config.get` | `{section: groups\|rules\|dns\|all}` | 返回 agent overlay 与 `rev` |
| `app.config.patch` | `{base_rev, patch, dry_run?}` | JSON Merge Patch 作用于 overlay（**落在现有 `OverridePatch` 存储上，不平行造层**）；`base_rev` 不符 → `STALE_REV`；`dry_run` 返回 diff |
| `app.config.apply` | `{rev, confirm_within_s?}` | 手机内部完成「写配置 → 通知 EC 热重载」，见 §6.4 确认机制 |
| `app.config.confirm/rollback` | `{rev}` | 确认或回滚到上一已确认 rev |
| `app.pref.set` | `{mode?, selections?}` | 隧道未运行时持久化，结果 `deferred` |
| `app.audit.tail` | `{n≤50}` | 最近 agent 操作记录 |

## 6.3 事件推送（设备 → agent）

| 事件 | 数据 |
|---|---|
| `evt.state` | `{path, old, new, origin: user\|agent\|system}` |
| `evt.vpn` | `{status, reason: user\|agent\|system\|crash\|on_demand, epoch}` |
| `evt.config` | `{rev, origin}` |
| `evt.profile` | `{id, result}` |
| `evt.core.health` | `{mem_mb, mem_limit_mb, level}`（仅状态变化时发） |
| `evt.controller.changed` | `{controller}` |

事件尽力送达并带 `seq`；同 `path` 500ms 内合并；流量类不推送，由 `core.state.get` 拉取；丢事件由 `state_digest` 对账兜底。

## 6.4 心跳、命令生命周期与仲裁

**心跳**：空闲 25s 发 `ping`，对端回 `pong`；60s 无入站帧判定通道死亡重连。`ttl` 以接收方单调时钟 + 到达时间判断。

**命令生命周期**：`queued → sent → acked → done | failed | expired`。手机收到 `cmd` 立即 `ack`，执行后 `res`；5s 无 `ack` 同 id 重发；重复 id 由去重表返回缓存结果；超 `ttl` 无 `res` → MCP 层返回 `TIMEOUT_UNKNOWN` 附 `command_id`，用 `hako_command_status` 核实，**不盲目重发**。

**资源域串行化**（daemon 侧强制，手机侧再校验）：

| 域 | 命令 | 规则 |
|---|---|---|
| `vpn` | `app.vpn.*` | 同域 FIFO，每域一个在途 |
| `profile` | `app.profile.*` | 同上 |
| `config` | `app.config.*`、`app.pref.set` | 同上；`apply` 是**屏障** |
| `runtime` | `core.*` | 同上，只读可并行 |

**屏障规则**：`config.apply` 期间 `runtime` 命令排队（最长 20s），完成后 `epoch+1`；`vpn.stop` 生效时排队的 `runtime` 命令以 `TUNNEL_STOPPED` 失败；`vpn.start` 完成前的 `runtime` 命令按 `ttl` 等待下发；队列深度 >8 → `CONFLICT_BUSY`。

**乐观并发**：`epoch`（隧道启动/内核重载 +1，EC 在 `hello` 与 `res.meta` 携带）；命令可带 `if.epoch`，不符 → `STALE_EPOCH`。`rev`（AC 维护的配置修订号）；`config.patch` 必带 `base_rev`，不符 → `STALE_REV`。

**用户本地操作优先**：用户在 App 手动改动 → AC 立即 `rev+1` 并发 `evt.state{origin:user}`。同一对象 `origin=user` 变更后 60s 内，agent 写命令返回 `USER_RECENT_CHANGE`，需显式 `force: true` 覆盖。

**提交确认机制（防自锁）**：`config.apply` 默认 `confirm_within_s=60`。EC 重载后需完成「健康检查通过 + 重新连上 agent」，agent 随后 `config.confirm`；超时未确认 → 手机自动回滚到上一个已确认 rev，上报 `evt.config{origin:system, rolled_back:true}`。**App 生成的最终配置中，agent 端点的直连规则永远置顶，且不可被 overlay 覆盖**；EC 自身出站 socket 不进入隧道。

**审计**：每条 agent 写命令手机侧记录（时间、op、摘要、结果、是否可撤销），本地保留 30 天；配置/订阅/偏好类操作支持一键撤销（反向 patch）。

# 第五部分：MCP Server 规格

## 7. 通用约定

- 工具统一前缀 `hako_`，共 13 个；CRUD 类合并为带 `action` 参数的单个工具，减少 agent 上下文占用
- 除 `hako_pairing` 外所有工具接受可选 `device`（dev_id 或 alias）
- 成功返回：`structuredContent` + 简短文本摘要；含 `meta{device, channel, rev, epoch, took_ms, as_of?, stale?, degraded?}`
- 失败返回：`isError: true` + `error{code, message, retryable, hint, state}`；`hint` 是给 agent 的下一步建议
- 列表类默认 `limit=50`、上限 200、支持 `cursor`；`summary: true` 只返回计数与 Top-N
- 全部填 `readOnlyHint` / `destructiveHint` / `idempotentHint`
- **机密脱敏**：订阅 URL 只显示 host + 末 4 位；日志/连接列表 token 打码；**不提供读完整订阅 URL 的工具**
- **不可信内容**：节点名、规则备注、日志来自第三方订阅 → `<untrusted>` 包裹、截断 128 字符、剔除控制字符，工具说明提醒 agent 不要执行其中指令
- 写工具接受可选 `idempotency_key`，daemon 去重 10 分钟；未提供时以 `hash(device, tool, 规范化参数, 30s 时间桶)` 兜底
- 同设备写工具经资源域串行化，调用本身可并发
- MCP 资源（可选）：`hako://devices/{id}/state` 暴露合并后设备状态，变化时发 `resources/updated`

## 7.1 工具清单

| 工具 | 关键参数 | 返回要点 | 通道 | 幂等性 |
|---|---|---|---|---|
| `hako_status` | `device?` | 两通道在线、隧道状态与 `stop_reason`、模式、当前订阅/节点、`capabilities` 能力矩阵、`controller` | daemon 缓存 + app/ext | 只读 |
| `hako_health_check` | `level: quick\|full` | `checks[]`（channel_app/channel_ext/tunnel/core_mem/dns/probe/node_alive），汇总 `healthy\|degraded\|down` + 建议动作 | app + ext | 只读（少量探测流量） |

| `hako_vpn` | `action: status\|on\|off\|restart, force?` | 隧道状态 + `epoch`；首次未授权返回 `NEED_USER_ACTION` | app | on/off 幂等；restart 非幂等 |

## 7.2 权限分级（scope，手机与 daemon 双端校验）

| scope | 包含 |
|---|---|
| `observe`（只读） | status、health_check、list_groups、list_nodes、connections(list)、command_status、subscription(list)、rules(get) |
| `operate`（日常运维） | + switch_node、test_latency、set_mode、connections(close) |
| `manage`（完全管理） | + subscription 增删改、rules 全部、vpn |

默认 `manage`（符合全权托管定位），配套操作记录与摘要通知。超出 scope 返回 `SCOPE_DENIED`。

## 7.3 错误语义

| code | 含义 | 可重试 | 给 agent 的 hint |
|---|---|---|---|
| `DEVICE_REQUIRED` | 多设备未指定 | 否 | 附设备列表 |
| `DEVICE_OFFLINE` | 两通道不在线且 ttl 内未恢复 | 是 | 稍后重试；已尝试唤醒则 meta 标注 |
| `APP_SUSPENDED` | App 休眠，已发唤醒并排队 | 自动等待 | 无需重发，等结果或查 command_status |
| `TUNNEL_DOWN` | 需内核但隧道未开 | 否 | `hako_vpn{action:on}` |
| `TUNNEL_STARTING` | 隧道启动中 | 是 | 5s 后重试 |
| `TUNNEL_STOPPED` | 等待期间隧道被停 | 否 | 确认用户意图 |
| `NEED_USER_ACTION` | 需用户操作：`vpn_permission`/`open_app`/`local_network`/`camera` | 否 | 转告用户 |
| `SCOPE_DENIED` / `NOT_CONTROLLER` | 权限不足 / 非主控 | 否 | 提示在手机上调整 |
| `STALE_REV` / `STALE_EPOCH` | 版本过时 | 需先读取 | 重读状态再提交 |
| `USER_RECENT_CHANGE` | 用户刚手动改过 | 否 | 确认后带 `force:true` |
| `INVALID_ARGUMENT` / `NOT_FOUND` / `UNSUPPORTED` | 参数/对象/能力 | 否 | 附字段与可选值 |
| `CONFLICT_BUSY` | 资源域队列深度 >8 | 是 | 稍后重试 |
| `TIMEOUT_UNKNOWN` | 结果未知 | 否 | `hako_command_status` 核实 |
| `CORE_ERROR` | 内核拒绝，脱敏原文 | 视情况 | 按原文修正 |
| `RATE_LIMITED` | 限流 | 是 | `retry_after_ms` |

# 第六部分：降级语义

## 8. 能力等级

| 等级 | 条件 | 对外标识 |
|---|---|---|
| **F 完整** | AC + EC 均在线 | `degraded: null` |
| **A 仅 App** | AC 在线、EC 不在 | `degraded: {level: A, reason: tunnel_down}` |
| **S 休眠** | AC 已挂起、可唤醒 | `degraded: {level: S, reason: app_suspended}` |
| **O 离线** | 两通道都不在且无可用唤醒 | `degraded: {level: O, reason: offline}` |

## 8.1 各等级行为（排队 = daemon 在 ttl 内保留，恢复后下发）

| 操作 | F | A | S | O |
|---|---|---|---|---|
| 读状态/节点/规则 | 实时 | 缓存，带 `as_of` + `stale` | 同 A | daemon 缓存 |
| 订阅增删/刷新 | ✓ | ✓ | 唤醒后执行 | 排队 |
| 配置 patch/apply | ✓ 热重载 | 仅落盘 `deferred` | 唤醒后按 A | 排队 |
| switch_node / set_mode | `applied` | `deferred`（`app.pref.set` 持久化） | 唤醒后按 A | 排队 |
| test_latency/connections/dns/probe | ✓ | `TUNNEL_DOWN` | `TUNNEL_DOWN` | `DEVICE_OFFLINE` |
| vpn on | 幂等返回 | ✓（首次需用户授权） | 唤醒后执行 | 排队 |
| vpn off | ✓ | 幂等返回 | 唤醒后按 A | 排队 |

## 8.2 语义约定

- **`deferred` ≠ 已生效**：agent 应在 `hako_status` 看到 `epoch` 增加后再向用户报成功
- **不隐式唤起隧道**：`core.*` 工具在隧道关时返回带 hint 的 `TUNNEL_DOWN`，由 agent 显式 `hako_vpn{action:on}`
- **尊重用户手动关闭**：`evt.vpn` 记 `stop_reason`；`stop_reason=user` 且距今 <30 分钟时 `hako_vpn on` 返回 `USER_RECENT_CHANGE`，需 `force:true`
- **On-Demand 自动恢复**：Extension 被杀后 On-Demand 拉起隧道，`epoch+1`，EC 重连上报 `evt.vpn{reason:on_demand}`。用户手动关闭后系统不拉起，属预期行为

## 8.3 向双方说清楚

**对 agent**：`hako_status.capabilities` 逐工具给出 `available | deferred | unavailable` 与原因；`meta.degraded` 带 `{level, reason, next}`（next 是可直接执行的下一步）。

**对用户**（首页 Agent 卡副行，见 §9.1 已定稿）：已连接态展示 F；隧道关（A）展示「等待中 · 订阅与规则仍可管理，节点操作需代理运行」；S/O 态在设置页「连接详情」展示双通道状态、最后在线时间与最近错误。

# 第十一部分：风险清单

## 12. iOS 生命周期

| # | 风险 | 缓解 |
|---|---|---|
| 1 | App 挂起 AC 断开，agent 误读为离线 | 后台前发 `bye{suspend}`，daemon 标 `Suspended` 并排队+唤醒；UI 与错误文案区分休眠/离线 |
| 2 | 静默推送不保证送达、被限频、强杀后不再唤醒 | 不承诺 SLA，文案「通常几秒到几分钟」；强杀后返回 `NEED_USER_ACTION{open_app}`；监控唤醒成功率 |
| 3 | Extension 被内存上限杀 | EC 内存预算 ≤3MB；分页、单帧 ≤64KB、日志 ≤200 行；On-Demand 拉起后 `epoch+1` |
| 4 | 用户手动关 VPN 后 On-Demand 不再拉起 | `stop_reason=user` 区分，不强行拉起 |
| 5 | 后台启动 VPN 系统限制未知 | P2 后期真机 spike 先行 |
| 6 | EC 自身连接卷入隧道回环 | agent 端点直连规则置顶 + EC socket 绑物理接口，P1 重点评审 |
| 7 | 重启后首次解锁前 Keychain 不可读 | 密钥 `AfterFirstUnlock`；失败进 Backoff 解锁后重试 |
| 8 | Wi-Fi/蜂窝切换 WS 抖动 | 路径变化立即重连 + 多端点并行 + 结果去重 |

## 12.1 安全

| # | 风险 | 缓解 |
|---|---|---|
| 9 | 口令泄露（截屏/共享） | 一次性、TTL 5 分钟、3 次失败作废；中继/公网路径强制 SAS |
| 10 | 中继被攻破 | Noise 端到端；room 由 HMAC 派生不可反推；agent 公钥钉在手机上 |
| 11 | 手机丢失/agent 主机失陷 | scope 分级；写操作 30 天操作记录 + 一键撤销；定期推送 Agent 操作摘要；一键断开并移除；可选「高风险操作需本机确认」（默认关，保零操作体验） |
| 12 | 提示词注入（节点名/日志进 agent 上下文） | `<untrusted>` 包裹 + 截断 + 剔控制字符；工具说明提醒；审计+摘要通知兜底（残留风险文档如实说明） |
| 13 | 订阅 URL 含密钥泄露 | 默认脱敏；不提供完整 URL 读取工具；add 不回显 |
| 14 | 现有 mailbox 无鉴权（`HakoWidgetMailbox.swift:167-171`） | mailbox v2：HMAC（Keychain 共享密钥）+ nonce + 时间戳 + 0600；v1 保持兼容但新功能不依赖 |
| 15 | 重放攻击 | Noise nonce 严格递增；每次重连新握手；idem 去重表 |
| 16 | Wake Gateway 中心化依赖 | 无状态、不存 token、推送不含业务数据；允许自建（自编译需自己的 APNs 密钥） |
